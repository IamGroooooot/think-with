# 채점 교정 기록

사람이 블라인드로 매긴 채점 기록입니다. 후보를 배포할지는 이 채점으로 정하고, LLM judge가 사람의 판단과 얼마나 맞는지 잴 때도 이 기록을 기준으로 씁니다. `claude plugin eval`이 실행하는 케이스가 아니므로 플러그인 패키지에는 포함되지 않습니다. 회차를 만들고 채점하고 결과를 여는 절차와 파일 형식은 내부 스킬 `blind-grade`(`src/internal/blind-grade/`)에 있습니다.

## 이름

- 회차 폴더: `<suite>-<후보>-vs-<기준>`. suite는 처음 보는 케이스를 낸 eval suite입니다.
- arm: 릴리스는 버전(`0.1.4`), 후보는 플러그인 전체에서 차례로 매긴 `r1`, `r2`, 플러그인을 설치하지 않은 상태는 `none`입니다.
- 실행 결과: `plugins/claude/think-with/<suite>/results/<arm>/`. 로컬에만 있고 git에서 제외됩니다. 같은 arm을 다시 실행한 결과는 `0.1.4-pilot1`처럼 뒤에 이름을 붙입니다.

## 후보

| arm | 내용 | 결과 |
|---|---|---|
| `r1` | lay-out 수정안 1 (`evals-holdout/PREREG.md`) | 배포하지 않음 |
| `r2` | lay-out 수정안 2 (`evals-holdout2/PREREG.md`) | 0.1.5로 배포 |

## 회차

모두 2026-09-29에 Claude Code 2.1.284로 실행했습니다. 쌍마다 쓴 실행 번호(0부터)는 각 회차의 `blind-key.json`에 있습니다.

| 회차 | 케이스 | 답변 출처 (`results/` 아래) | 결과 |
|---|---|---|---|
| `evals-0.1.4-vs-none` | dev 01, 02, 04, 05, 06 | `evals`: `0.1.4-pilot3`의 with와 without | 더나음은 매기지 않음. 관계 X는 none만 2개 |
| `evals-holdout-r1-vs-0.1.4` | h1–h4, dev 05 | `evals-holdout`: `r1`, `0.1.4`. 05는 `evals`: `r1`, `0.1.4` | r1 0승 2패 3무 |
| `evals-holdout2-r2-vs-0.1.4` | f1–f4, dev h1, h3 | `evals-holdout2`: `r2`, `0.1.4`. h1, h3는 `evals-holdout`: `r2`, `0.1.4` | r2 4승 1패 1무, 배포 규칙 충족 |

`evals-0.1.4-vs-none`에서 플러그인이 없는 답변은 첫 줄에 명령이 설치되어 있지 않다고 써서 정체가 드러나므로, 그 줄만 지웠습니다.

## 채점 기준

- 관계: O는 핵심 관계가 정확히 보임, △는 내용은 있지만 애써야 보임, X는 틀렸거나 보이지 않음.
- 낭비: 0은 불필요한 내용 없음, 1은 약간 있음, 2는 뚜렷하게 있음.
- 형태(선택): O는 관계에 맞는 표현 형태, X는 맞지 않는 형태.
- 메모(선택): 한 줄 의견.
- 더나음: A, B, 같음 중 하나. 답변마다 채점을 마친 뒤에 매깁니다.

빈칸은 채점하지 않았다는 뜻입니다.
